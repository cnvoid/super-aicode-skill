# response — 统一响应封装规范

## error 级别硬约束

### 1. 所有接口必须使用统一响应外壳

每个 HTTP 接口的响应体必须包裹在统一的响应结构中，不得裸返业务数据。

统一响应外壳必须包含以下三个字段：

- `code`：整型状态码。0 表示成功，非 0 表示异常。
- `message`：字符串描述。成功时固定为 "ok"，失败时为可读的错误描述。
- `data`：泛型数据载体。成功时承载业务数据，失败时可为 null。

后文约定称为「标准响应体」。

### 2. 成功响应 code 必须为 0

当接口处理成功时，HTTP 状态码为 200，响应体的 code 字段必须为 0，message 必须为 "ok"，业务数据放入 data 字段。

不得使用 HTTP 201/204 等状态码表示业务成功——统一使用 200 + code=0 的约定，业务状态由响应体表达。

### 3. 分页响应必须固定 data 结构

分页查询接口的 data 字段必须为以下固定结构：

- `list`：当前页的数据列表，数组类型
- `total`：符合查询条件的总记录数，整型
- `page`：当前页码，整型（从 1 开始）
- `pageSize`：每页条数，整型

分页响应整体仍包裹在标准响应体中（code=0 + message="ok" + data={list, total, page, pageSize}）。

### 4. 错误响应必须统一结构

当接口处理失败时，HTTP 状态码应为业务语义对应的状态码（见下方对照表），响应体的结构为：

- `code`：错误码（非 0 整型）
- `message`：面向开发者的错误描述
- `traceId`：用于日志追踪的唯一标识
- `data`：可为 null

### 5. 常用错误码与 HTTP 状态码对照表

| 场景 | HTTP 状态码 | code | message 示例 |
|------|-----------|------|-------------|
| 成功 | 200 | 0 | ok |
| 参数校验失败 | 400 | 400 | 参数校验失败: userId 不能为空 |
| 未认证 | 401 | 401 | 未登录或 Token 已过期 |
| 无权限 | 403 | 403 | 无此操作权限 |
| 资源不存在 | 404 | 404 | 订单不存在 |
| 请求方法不允许 | 405 | 405 | 不支持 POST 方法 |
| 数据冲突 | 409 | 409 | 订单状态已变更，请刷新后重试 |
| 业务规则不满足 | 422 | 422 | 库存不足 |
| 请求过于频繁 | 429 | 429 | 操作过于频繁，请稍后重试 |
| 服务器内部错误 | 500 | 500 | 系统繁忙，请稍后重试 |
| 网关错误 | 502 | 502 | 上游服务不可用 |
| 服务暂不可用 | 503 | 503 | 系统维护中 |
| 网关超时 | 504 | 504 | 上游服务响应超时 |

对于业务自定义错误码（如订单模块的"商品已下架"、"优惠券已过期"等），建议使用 6 位编码，前 3 位为模块标识，后 3 位为具体错误：
- 100001-100999：用户模块
- 200001-200999：订单模块
- 300001-300999：商品模块
- 400001-400999：支付模块

### 6. 禁止以下行为

- 响应体不使用统一外壳，直接返回业务数组或对象
- 成功响应的 code 使用非 0 值
- 在响应体中混用下划线和驼峰命名（全文统一驼峰）
- 分页接口返回的 data 结构不一致（有的叫 list、有的叫 records、有的叫 items）
- 错误响应不返回 traceId，导致无法追踪问题

## warn 级别软约束

- 时间字段统一使用 ISO 8601 格式字符串（而非时间戳数字），便于前后端直接使用
- null 值字段统一省略而非返回 null（减少响应体积）
- 响应体中的数字类型金额字段使用字符串而非数字（防止精度丢失）
- 在接口文档中明确标注每个字段的 null 可能性
- 布尔字段统一使用 is/has/can 前缀命名
