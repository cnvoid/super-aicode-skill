# logging — 结构化日志规范

## error 级别硬约束

### 1. 使用结构化日志

日志必须以键值对形式输出，便于日志系统采集、索引和分析。禁止使用纯文本拼接日志消息。

推荐格式：JSON 格式，每行一条日志记录。字段至少包含 timestamp、level、message。

### 2. 禁止日志中使用字符串拼接构建消息

日志消息中的动态数据必须通过结构化字段传递，不得拼接到消息字符串中。字符串拼接导致日志无法被结构化检索。

### 3. 异常日志必须包含完整异常对象

记录 ERROR 级别日志时，必须将异常对象作为独立字段传入（而非仅记录异常的消息文本），确保堆栈信息完整保留。

### 4. 敏感信息必须脱敏

日志中不得明文输出以下敏感信息：手机号、身份证号、银行卡号、密码、Token、邮箱地址、家庭住址。

脱敏规则：保留首尾字符，中间用星号替换。如手机号保留前 3 后 4 位。

## warn 级别软约束

### 1. 日志级别使用规范

- ERROR：系统异常，需人工介入（数据库连接失败、依赖服务不可用）
- WARN：降级执行、重试、可恢复的业务异常（库存不足、用户余额不足）
- INFO：关键业务节点（订单创建、支付完成）、服务启动关闭、定时任务执行
- DEBUG：详细执行过程，用于开发调试

### 2. trace-id 全链路传递

每个请求必须生成唯一 trace-id，并在该请求的所有日志中携带。trace-id 需在微服务调用间跨进程传递（通过 HTTP Header 或消息队列元数据）。

### 3. 日志量控制

- 循环体内禁止使用 INFO 及以上级别日志
- 高频接口（QPS > 100）增加日志采样率
- 单条日志记录不超过 1KB
