# resilience — 容错容灾规范

## error 级别硬约束

### 1. 外部调用必须设置超时

所有访问外部系统（数据库、缓存、HTTP 服务、消息队列）的操作必须有显式的超时控制，不得使用无超时的默认配置。

超时时间参考值（可根据实际 SLA 调整）：
- 数据库：连接超时 ≤ 3s，查询超时 ≤ 10s
- HTTP 调用：连接超时 ≤ 3s，读取超时 ≤ 15s
- Redis/缓存：连接超时 ≤ 1s，操作超时 ≤ 3s
- 消息队列：发送超时 ≤ 5s

超时设置需要在代码中显式配置，不得依赖底层库的默认值。

### 2. 服务必须支持优雅关闭

应用进程在收到终止信号（SIGTERM、SIGINT）后，必须：
- 停止接收新的请求
- 等待正在处理的请求完成（设置最大等待时间）
- 关闭数据库连接池
- 关闭消息队列连接
- 刷新日志缓冲区

优雅关闭的总超时时间建议 30s，超时后强制退出。

### 3. 资源使用后必须释放

数据库连接、HTTP 连接、文件句柄、锁等资源，使用完毕后必须在 finally/defer 块中确保释放，不得依赖垃圾回收。

## warn 级别软约束

### 1. 关键外部调用应具备重试能力

对于网络调用、消息发送等可重试的操作，应配置重试策略：
- 最大重试次数：3 次
- 退避策略：指数退避（100ms → 200ms → 400ms）加随机抖动
- 仅对可重试异常重试（网络超时、503、连接拒绝），不对业务异常重试

### 2. 关键路径应有降级方案

核心业务路径中依赖的外部服务应有降级策略：
- 读取场景：主库失败 → 读缓存 → 返回默认值
- 写入场景：同步失败 → 异步队列 → 定时补偿

降级发生时必须记录日志，说明降级原因和降级路径。

### 3. 写操作需保证幂等

涉及资金、库存、订单等关键数据的写操作，需提供幂等机制：通过幂等键（如请求 ID、业务单号）在指定时间窗口内对相同请求返回已有结果，避免重复执行。
