# doc — 文档注释规范

## error 级别硬约束

### 1. 所有 public 函数必须有文档注释

每个对外暴露的函数（public/exported）必须在定义处包含文档注释，说明：
- 函数的功能和用途
- 每个参数的含义和约束
- 返回值的含义
- 可能抛出的异常及触发条件

文档注释格式遵循语言惯例：Java 使用 JavaDoc，Go 使用行注释（会被 godoc 提取），TypeScript 使用 JSDoc。

### 2. 注释解释"为什么"而非"是什么"

注释的价值在于解释代码背后的意图、决策原因和约束条件。不要用注释复述代码本身已经表达的信息。

需要注释的场景：
- 非直观的算法选择（为什么选用这个算法而非另一个）
- 业务规则的原因（为什么这个场景需要悲观锁）
- 临时方案的说明（为什么使用 workaround，何时移除）
- 边界值的选择理由（为什么超时设为 3s 而非 5s）

不需要注释的场景：
- 变量赋值的字面描述
- getter/setter 的重复说明
- 显而易见的代码逻辑

### 3. 复杂逻辑必须有注释说明

以下场景必须在代码块上方添加注释：
- 超过 3 个分支的条件判断（说明各分支的业务含义）
- 正则表达式（说明匹配规则和意图）
- 位运算（说明每个位的含义）
- 复杂的状态流转（说明状态机规则）
- 性能敏感的代码（说明为何这样写能提升性能）

## warn 级别软约束

- 模块/类的顶部注释说明其职责边界和核心依赖
- 对外 API 的接口定义附带使用示例
- 弃用的方法标注弃用原因和替代方案
- 顶层文档（README）与实际代码保持同步更新
