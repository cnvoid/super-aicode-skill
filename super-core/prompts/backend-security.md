# backend-security — 后端安全规范

## error 级别硬约束

### 1. SQL 注入防范：必须使用参数化查询

所有数据库查询必须使用参数化查询或 ORM 的安全 API，禁止通过字符串拼接构建 SQL 语句。

各语言的正确做法：
- Java JDBC PreparedStatement：使用 ? 占位符 + setParameter
- Java JPA/Hibernate：使用 JPQL 命名参数（:paramName）或 Criteria API
- Go database/sql：使用 ? 或 $1 占位符 + args 参数传递
- Node.js：使用 ORM 的安全查询方法，禁止直接拼接 raw query

动态排序字段、动态表名等无法使用占位符的场景，必须使用白名单校验——仅允许代码中预定义的安全值，不得直接接收用户输入。

### 2. CORS 必须配置白名单

跨域资源共享的配置必须使用允许来源白名单，禁止使用通配符 * 放行所有来源。

允许的来源必须精确指定（https://www.example.com），不得使用正则表达式模糊匹配。开发环境如需便捷调试，可将 localhost 地址加入白名单，但仅限 dev 环境。

### 3. 敏感接口必须限流

以下类型的接口必须配置请求频率限制：

- 登录接口：同一 IP 不超过 5 次/分钟，同一账号不超过 3 次/分钟
- 注册接口：同一 IP 不超过 3 次/分钟
- 发送验证码：同一手机号/邮箱不超过 1 次/分钟，不超过 5 次/天
- 密码重置：同一账号不超过 2 次/小时

限流策略在认证之前执行，防止恶意请求绕过认证消耗资源。限流超限后返回 429 状态码。

### 4. 密码必须使用安全算法加密存储

用户密码在数据库中不得明文存储。必须使用以下密码哈希算法之一进行单向加密：

- bcrypt（推荐，cost ≥ 10）
- argon2id（推荐，内存消耗 ≥ 64MB）
- scrypt（可接受）

禁止使用的算法：MD5、SHA1、SHA256（不加盐或弱盐）、Base64 编码。

密码加密必须由服务端完成，不得在前端加密后直接入库（前端加密仅保护传输过程，不替代服务端哈希）。

### 5. 请求签名防篡改

对外部开放的高敏感接口（支付回调、开放平台 API），必须对请求进行签名校验，防止请求被篡改或重放。

签名方案：请求参数 + 时间戳 + 随机数 + 签名密钥 → 生成签名 → 服务端重新计算并对比。签名不匹配 → 拒绝请求。

## warn 级别软约束

- 返回给前端的错误信息避免暴露内部实现细节（如表结构、框架版本、堆栈信息）
- CSRF Token 机制用于处理 Cookie 认证场景下的跨站请求伪造
- 文件上传接口限制文件大小和类型，服务端重新校验 MIME 类型（不信任客户端 Content-Type）
- 生产环境的 Swagger/API 文档页面禁止对外公开或添加访问密码
- 第三方 SDK/依赖库定期扫描已知漏洞（使用 Snyk、Dependabot、Trivy）
