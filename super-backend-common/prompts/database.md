# database — 数据库设计规范

## error 级别硬约束

### 1. 表设计必须声明主键和必要约束

每张数据表必须包含以下基础设计：
- 主键：自增整数（小表）或分布式 ID（分库分表场景）。雪花算法/号段模式二选一，禁止使用 UUID 字符串作为聚簇索引的主键。
- 创建时间和更新时间字段，并配置自动填充。
- 逻辑删除标记字段（如 is_deleted），用于软删除场景。金融/对账类数据禁用逻辑删除，使用归档表。
- 乐观锁版本号（如 version 字段），用于并发写冲突检测。

### 2. 索引必须按查询模式设计

索引设计必须基于实际的查询场景，不得凭猜测创建。设计原则：
- WHERE 条件中的高频字段建索引
- ORDER BY 和 GROUP BY 字段建索引
- 多列索引遵循最左前缀原则，高频查询字段放最左
- JOIN 的外键字段建索引
- 覆盖索引优先考虑，减少回表查询

禁止的行为：
- 每列单独建索引（要建联合索引）
- 在大表上对低基数字段（如性别、布尔值）建索引
- 在频繁更新的字段上建过多索引
- 不分析执行计划直接上线索引

### 3. 数据库迁移脚本必须可重复执行和可回滚

数据库表结构变更必须通过迁移脚本管理，不得手动执行 SQL 修改表结构。

迁移脚本要求：
- 每个版本有对应的升级脚本和回滚脚本
- 升级脚本必须可重复执行（使用 IF NOT EXISTS 等幂等操作）
- 迁移脚本纳入版本控制，与代码同步提交
- 生产环境执行迁移前备份数据库

工具选型：Java 用 Flyway 或 Liquibase，Node.js 用 Prisma Migrate，Go 用 golang-migrate。

### 4. 连接池必须合理配置

数据库连接池必须显式配置，核心参数：
- 最大连接数：不超过数据库 max_connections 的 50%，为运维和管理连接预留容量
- 最小空闲连接：5-10 个，减少冷请求的连接建立开销
- 连接超时：≤ 3s
- 空闲连接存活时间：≤ 10 分钟（低于数据库的 wait_timeout）
- 连接泄漏检测：开启 abandoned connection 回收，超时阈值 30 分钟

禁止使用连接池的默认配置而不调整。

## warn 级别软约束

- 大表（>1000 万行）考虑水平分表，按时间或按业务 ID 哈希分片
- 读多写少的场景考虑读写分离，事务操作走主库，查询走从库
- 批量操作每批次 500-1000 条，避免长事务和锁表
- 慢查询日志开启，超过 1 秒的 SQL 进行分析优化
