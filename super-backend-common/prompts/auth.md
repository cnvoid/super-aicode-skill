# auth — 认证鉴权规范

## error 级别硬约束

### 1. 认证与授权必须分离

认证（验证身份）和授权（验证权限）必须是两个独立的流程，不得混淆。认证失败返回 401，授权失败返回 403。

认证层负责：验证用户身份（密码/Token/OAuth）、颁发凭证（JWT/Session Token）、刷新凭证。

授权层负责：验证用户是否有权限执行当前操作（角色检查/资源归属检查）。授权逻辑不应散落在每个 Controller 方法中，必须通过中间件/拦截器/守卫统一执行。

### 2. Token 必须设置过期时间且有刷新机制

JWT 或 Session Token 必须设置合理的过期时间：
- Access Token：15 分钟 - 2 小时
- Refresh Token：7 天 - 30 天

禁止发放永不过期的 Token。Refresh Token 使用一次后即失效并颁发新的 Refresh Token（Refresh Token Rotation），检测到已失效的 Refresh Token 被再次使用时视为 Token 泄露，立即吊销该用户所有凭证。

Access Token 存储于内存（前端），Refresh Token 存储于 httpOnly Cookie。

### 3. 密码必须满足强度策略

用户密码必须满足最低强度要求：
- 长度 ≥ 8 位
- 包含大写字母、小写字母、数字
- 不得包含连续重复字符（如 aaa）
- 不得为常见弱密码（Password123、12345678 等）

密码存储使用 bcrypt（cost ≥ 10）或 argon2id。密码修改时需验证旧密码。连续输入错误密码 5 次后临时锁定账号 15 分钟。

### 4. 权限模型必须显式声明

项目的权限模型必须在代码中以显式方式定义，不得靠隐式的"前端隐藏按钮"实现权限控制。

权限控制粒度：
- 接口级：通过注解/装饰器标注所需角色或权限码
- 数据级：查询时自动按用户所属组织/角色过滤数据范围

权限码集中定义在枚举或常量文件中，不得在代码中硬编码权限字符串。

## warn 级别软约束

- 敏感操作（删除、导出、修改权限）需二次确认或验证码
- 异地登录/IP 变更发送通知
- 登录日志和操作审计日志保留 90 天以上
- 第三方 OAuth 登录时校验 state 参数防 CSRF
- 手机/邮箱验证码有效期 5 分钟，使用后立即失效
