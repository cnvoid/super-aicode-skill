# report — 周期性总结报告生成规范

## error 级别硬约束

### 1. 周报/月报必须基于实际日志数据生成

生成周报/月报时，必须读取 `WORKLOG.md` 文件提取对应时间段的实际记录，不得凭空编造：

- 先定位时间范围对应的日志条目（通过 `### YYYY-MM-DD` 标题定位）
- 未覆盖的时间段标注 "暂无记录"
- 每条报告中的事项必须能从日志文件中追溯到原始记录

### 2. 周报必须包含以下模块

```
# {项目名} 周报 ({起止日期})

## 一、本周完成事项
（按类型分组汇总已 [x] 的事项，摘要 + 工时）
- ...

## 二、进行中事项
（近期未标记完成的活跃事项）
- ...

## 三、下周计划
（结合上下文推测后续工作，标注"待确认"）
- ...

## 四、风险与阻碍
（标注遇到的问题、资源不足、外界依赖等阻塞项）
- ...

## 五、数据概览
- 本周完成：N 项
- 本周工时合计：Mh
- 类型分布：feature N, fix N, refactor N, ...
```

### 3. 月报必须在周报基础上汇总，不可重复统计

月报的生成规则：

- 汇总当月所有周报内容（如已有周报），未生成周报的部分从原始日志重新提取
- 按模块维度重新归类，展示每个模块的月度完成量和工时分布
- 月报新增模块：

```markdown
## 月度总览

| 模块 | feature | fix | refactor | test | doc | ops | 其他 | 工时合计 |
|------|---------|-----|----------|------|-----|-----|------|---------|
| 订单模块 | 3 | 2 | 0 | 1 | 0 | 0 | 0 | 18h |
| 用户中心 | 1 | 1 | 1 | 0 | 2 | 0 | 0 | 12h |
| ...

## 月度趋势分析
- 本月重点投入模块：{排名前三的模块}
- 技术债/修复占比：{fix+refactor 工时 / 总工时 * 100}%
- 测试覆盖率变化（如有数据）
```

### 4. 输出路径

- 周报输出到 `reports/weekly/{起止日期}.md`
- 月报输出到 `reports/monthly/{月份}.md`
- 首次输出自动创建对应目录
- 如果目录和文件已存在，追加模式（覆盖同周期旧报告的提示确认）

## warn 级别软约束

- **周报发送建议**：推荐每周五 17:00 前输出，给团队留出 review 时间
- **月报发送建议**：推荐每月最后一个工作日 16:00 前输出
- **风险标注**：持续超过 2 周未解决的风险项在月报中高亮标注
- **里程碑对齐**：建议标注当前 sprint/milestone 的完成进度百分比
- **图表建议**：月报建议补充燃尽图数据或工时趋势描述文字

## 报告生成工作流

```
用户："生成本周周报"
  ↓
1. 确认时间范围（本周一至周五，或用户指定范围）
2. 读取 WORKLOG.md，提取该时间段的所有条目
3. 按类型分组，按模块归类，统计工时
4. 检查是否有未完成的活跃事项 → 归入"进行中"
5. 结合上下文推断下周可能的后续工作 → "下周计划"
6. 询问是否有阻塞项需要写进"风险与阻碍"
7. 按模板输出报告 → 写入 reports/weekly/ 目录
8. 在日志中追加一条 review 类型记录："生成本周周报 — 耗时 0.5h"
```
