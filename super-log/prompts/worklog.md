# worklog — 工作事项记录规范

## error 级别硬约束

### 1. 必须有日志文件

项目根目录或配置指定路径下必须有工作日志文件。默认文件名 `WORKLOG.md`，可通过配置 `scenarios.log.worklog_file` 自定义。

- 若文件不存在，自动创建并写入文件头：

```markdown
# 工作日志

> 自动生成，由 super-log 技能维护。手动编辑时请保持格式一致。

```

### 2. 每条记录必须包含时间戳和分类

每条记录必须按以下格式写入：

```markdown
### YYYY-MM-DD
- [x] **{类型}** [{模块}] {事项描述} — 耗时 {N}h | 关联 #{issue}
```

字段要求：
- **日期**：`### YYYY-MM-DD` 作为三级标题，同一日期下汇聚当天所有记录
- **类型**：必须为以下枚举之一，不得自创：
  - `feature` — 新功能开发
  - `fix` — Bug 修复
  - `refactor` — 重构/优化
  - `test` — 测试编写/执行
  - `doc` — 文档编写
  - `ops` — 运维/部署/环境
  - `research` — 调研/技术预研
  - `review` — 代码评审
  - `other` — 其他事项
- **模块**：所属系统模块名，如 `订单模块`、`用户中心`，用 `[]` 包裹
- **描述**：一句话概括，精炼准确，40 字以内
- **耗时**：单位小时，允许小数，如 `2.5h`，不可省略
- **关联**：关联的 issue/PR/TAPD 编号，可选，无关联时写 `-`

### 3. 同一事项不得重复记录

写入前必须检查当日是否已有相同描述的事项：
- 完全相同 → 跳过，不重复追加
- 描述相似但不同 → 追加并标注差异点
- 进度更新 → 在原条目后追加子列表：

```markdown
- [x] **feature** [支付模块] 实现微信支付对接 — 耗时 4h | 关联 #1203
  - 已完成：统一下单、支付回调 (3h)
  - 进行中：退款接口对接 (1h)
```

### 4. 自动触发记录的场景

以下场景必须自动追加记录（无需用户明确指令）：
- super-core Phase 4 自检通过后
- `todowrite` 中任意任务状态变为 `completed`
- 用户说"完成了"/"做完了"/"OK"/"可以了"等完成确认词

记录时附带识别到的关联信息：
- 当前 git 分支名 → 关联模块名
- 生成的/修改的文件路径列表 → 在描述中体现

## warn 级别软约束

- **日汇总**：每日最后一条记录后建议添加统计行 `> 今日完成 N 项，耗时合计 Mh`
- **模块标签**：模块名建议保持与项目技术模块划分一致，避免随意命名
- **关联补全**：有 issue tracker 的项目，如用户提供编号，必须填写关联字段
- **耗时准确性**：耗时建议精确到 0.5h，避免过于粗放的 8h 整数目
- **连续记录**：建议每日至少一条记录，连续 3 天无记录时提醒用户

## off 规则说明

此规则关闭时，不再自动追加记录到日志文件，仅在用户明确请求时手动记录。
