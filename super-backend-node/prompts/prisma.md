# prisma — Prisma 规范

## error 级别硬约束

### 1. 查询必须使用 select 或 include 精确指定字段

所有数据库查询必须通过 select 或 include 显式声明需要的字段，不得使用默认的全字段查询。精确查询可以：
- 减少数据传输量
- 避免大字段（如 TEXT/BLOB）的无谓加载
- 允许数据库利用覆盖索引优化

关联查询通过 include 加载关联数据，并使用 select 限制关联数据中需要的字段。

### 2. 写操作必须使用事务保证一致性

涉及多表写操作的业务逻辑必须使用 Prisma 事务确保数据一致性。事务类型选择：
- 交互式事务（$transaction(fn)）：适用于需要根据查询结果决定后续操作的场景
- 批量事务（$transaction([...])）：适用于独立操作的批量执行

事务回调函数内需处理所有可能的异常，确保事务失败时数据回滚。

### 3. 必须为高频查询字段创建索引

在 Prisma Schema 中，对以下场景的字段使用 @@index 创建数据库索引：
- WHERE 条件中频繁使用的字段
- ORDER BY 排序字段
- 关联查询的外键字段

索引创建需权衡查询性能和写入性能，不宜对每个字段逐一加索引。

## warn 级别软约束

- 开发环境使用 prisma migrate dev 生成迁移文件，生产环境使用 prisma migrate deploy
- 使用 @@map 和 @map 控制生成的表名和列名符合命名约定
- 数据库连接池大小需匹配实际并发量和数据库连接上限
- 使用 Prisma 中间件实现全局的查询日志、软删除等功能
