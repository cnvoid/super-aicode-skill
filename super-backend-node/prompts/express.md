# express — Express 规范

## error 级别硬约束

### 1. 必须有全局错误处理中间件

Express 应用必须在所有路由和中间件之后注册一个全局错误处理中间件（四个参数的中间件函数），统一捕获所有未处理的异常并返回标准错误响应。

错误处理中间件的职责：
- 根据异常类型返回对应的 HTTP 状态码（业务异常 → 400/404/409，认证异常 → 401/403，未知异常 → 500）
- 返回统一结构的错误响应（包含 code、message、traceId）
- 记录完整的错误日志（包含堆栈和请求上下文）
- 不得泄露内部实现细节到响应中

### 2. 异步路由处理函数必须包裹异常转发

Express 不自动捕获 async 函数中抛出的异常。所有异步路由处理函数必须通过包装器将异常转发到 next 函数，确保被全局错误处理中间件捕获。

包装器实现：定义一个高阶函数，接收 async 函数作为参数，返回一个新的中间件函数，内部使用 Promise.resolve 包裹原函数并在 .catch 中调用 next。

### 3. 中间件链设计须清晰

路由的中间件链应按功能拆分为独立中间件，每个中间件职责单一。典型顺序：请求日志 → 认证 → 授权 → 参数校验 → 限流 → 业务逻辑。

不得在一个中间件中混合多个职责。

## warn 级别软约束

- 路由按业务模块拆分到独立的 Router 文件，主文件只做挂载
- 请求体大小限制在合理范围（如 1MB），防止恶意大请求
- 使用 helmet 中间件设置安全相关 HTTP 头
- 生产环境配置 CORS 白名单
