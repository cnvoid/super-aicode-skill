# association — 关联数据正确性规范

## error 级别硬约束

### 1. 外键必须指向真实存在的记录

所有引用其他表的字段（外键）必须指向测试库中真实存在的记录，禁止编造不存在的 ID。

- 插入子表前，必须确认父表记录已存在（查询其真实主键，或用已知的固定 ID）
- 引用已存在的历史数据时，先查询可用 ID 列表再随机/顺序抽取
- 禁止写死一个假设存在、但从未验证过的外键值

### 2. 按依赖拓扑顺序插入

造数必须遵循依赖顺序，先父后子，禁止先插子表再补父表：

```
第 1 层：无依赖的表（字典、枚举、状态、配置）
第 2 层：主数据表（用户、部门、角色、权限、商品、供应商）
第 3 层：业务表（订单、支付、工单），引用第 2 层主数据
第 4 层：关联/明细表（订单明细、用户-角色多对多），引用第 2/3 层
```

每一层插完再插下一层，跨层引用一律从已插入的数据中取真实主键。

### 3. 枚举、字典、状态表必须先插入且取值一致

- 字典/枚举表（如性别、订单状态、支付方式）必须在业务表之前插入
- 业务表中引用枚举的字段，取值必须与字典表定义完全一致（编码、值、含义）
- 禁止业务表引用了字典表中不存在的编码值

### 4. 复用已有主数据，避免孤儿与重复

- 用户、部门、角色、权限等主数据优先复用测试库中已存在的记录，避免造出无人归属的孤儿数据
- 若主数据不存在，先造主数据，再让业务数据引用
- 同一实体不可重复插入（以唯一键判断，重复则跳过或 upsert）

## warn 级别软约束

- 关联字段优先从已有主数据中随机抽取，使每条业务数据挂靠不同的父记录，贴近真实分布
- 多对多关联表要保证两端 ID 都真实存在，且同一组合不重复
- 引用关系造完后，用一条 JOIN 查询自检，确认无 NULL 外键、无指向不存在的 ID
