# generation — 测试数据生成规范

## error 级别硬约束

### 1. 数据必须业务语义仿真，禁止无意义占位

造出的数据必须符合字段语义，能支撑接口联调与演示，禁止用 `test`、`123`、`xxx` 之类无意义占位符填满整表。

- 姓名：真实感中文/英文姓名
- 手机号：符合号段规则的虚拟号码（如 13x/15x/18x）
- 金额：符合业务量级的合理小数，保留正确精度
- 时间：合法且前后关系合理（如 `created_at < updated_at`，`start_time < end_time`）
- 状态字段：从该字段枚举定义中取值，禁止编造不存在的状态值
- 文本字段：长度符合 `length`/`max_length` 约束，描述字段要通顺

### 2. 使用语言惯用的随机数据工具

优先使用语言生态主流的 faker 类库生成仿真数据，禁止手写大量硬编码数组：

| 语言 | 推荐工具 |
|------|---------|
| Java | `datafaker` / `java-faker` |
| Node.js | `@faker-js/faker` |
| Go | `gofakeit` / `brianvoe/gofakeit` |
| Python | `Faker` |

faker 库需固定随机种子（seed），保证每次生成结果可复现，便于排查问题。

### 3. 覆盖边界值与异常反例

除正常数据外，必须同时造出能覆盖接口测试的正反两类数据：

- 边界值：最大长度、最小值、最大值、临界金额、临界时间
- 异常反例：超长字符串、非法枚举值（若业务允许传入）、空串、负值
- 不同状态分布：各业务状态至少各 1 条（如订单的待支付/已支付/已取消）

不得只造"看起来漂亮"的正常数据，导致边界和异常路径无法验证。

### 4. 敏感信息必须脱敏

造数禁止使用真实个人隐私数据：

- 手机号、身份证、银行卡号使用符合规则但**不真实存在**的号段
- 密码、密钥、token 使用测试专用占位值，禁止复用线上真实凭证
- 涉及脱敏字段（姓名、邮箱）可使用仿真值，但不得指向真实个人

## warn 级别软约束

- 数据分布贴近真实业务：时间戳在合理区间内随机分布，状态按真实比例分布而非均匀
- 生成器与业务代码解耦，独立放在 seed / fixture / mock-data 目录，不污染业务逻辑
- 大数据量场景使用批量插入（每批 500-1000 条），避免逐条插入拖慢初始化
