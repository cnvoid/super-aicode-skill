# exception — 全局异常处理规范

## error 级别硬约束

### 1. 必须实现全局异常处理器

项目必须有统一的全局异常处理组件，用于捕获 Controller 层抛出的所有异常并转换为标准 HTTP 响应。不同框架对应的实现方式：
- Spring Boot: @RestControllerAdvice + @ExceptionHandler
- 裸 Servlet：Filter 或顶层 try-catch

全局异常处理器按异常类型分级处理：
- 业务异常（自定义异常） → 返回对应的 HTTP 状态码和业务错误码
- 参数校验异常（框架校验失败） → 返回 400 + 校验失败字段详情
- 认证授权异常 → 返回 401/403
- 未知异常（兜底） → 返回 500 + 通用错误信息，记录完整堆栈

### 2. 建立统一的业务异常体系

项目必须定义一个顶层异常基类，至少包含整型错误码和字符串错误消息。所有业务异常继承该基类并按模块组织。

异常构造函数应支持：
- 传入 cause 异常以保留异常链
- 传入可变参数用于构建错误消息中的动态信息

### 3. 参数校验失败统一由框架处理

使用声明式校验框架（JSR303 Bean Validation）对请求参数进行校验，校验失败时由全局异常处理器统一捕获框架抛出的校验异常并转换为标准错误响应。不得在 Controller 方法体内手写校验逻辑。

## warn 级别软约束

- 错误码按业务模块分段管理，使用 6 位编码：前 3 位为模块标识，后 3 位为具体错误（如 100001-100999 用户模块，200001-200999 订单模块，300001-300999 商品模块，400001-400999 支付模块）
- 异常消息仅描述技术细节供开发者排查，不直接暴露给终端用户
- 对外 API 的错误响应统一使用 code、message、traceId 三段式结构
