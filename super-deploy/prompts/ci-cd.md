# ci-cd — CI/CD 规范

## error 级别硬约束

### 1. 必须有多环境流水线

项目必须配置至少以下三个环境的 CI/CD 流水线：

- Dev：代码合入开发分支时自动构建 + 部署到开发环境
- Staging：代码合入主分支时自动构建 + 部署到预发布环境 + 冒烟测试
- Prod：手动触发或审批后部署到生产环境，支持一键回滚

流水线文件纳入版本控制，与代码同步维护。不得仅在 CI 平台 Web UI 手动配置流水线。

### 2. 构建产物必须版本化存储

每次构建产生的产物必须携带唯一版本号（commit SHA 或语义化版本号），并上传到制品仓库（Docker Registry、Nexus、Artifactory）。生产部署必须从制品仓库拉取已测试的产物，禁止从构建机器直接复制部署。

制品仓库中的镜像必须配置清理策略，保留最近 30 天的构建产物。

### 3. 部署必须支持回滚

每次生产部署前必须记录当前版本信息，确保部署失败时能快速回滚到上一个稳定版本。回滚操作不应依赖重建构建流程，直接使用制品仓库中的上一版本产物。

回滚操作必须可在 5 分钟内完成。

## warn 级别软约束

- 提交前自动运行 lint + 单元测试，失败则阻断合入
- 构建阶段包含安全扫描（依赖漏洞扫描、镜像漏洞扫描、SAST）
- 生产部署采用滚动更新策略，maxSurge=1、maxUnavailable=0 保证零停机
- 部署后自动运行冒烟测试，验证核心接口可用
- 分支策略：主分支保持可发布状态，功能分支合入前必须通过 CI
- 敏感配置（数据库密码、API Key）通过 CI 变量或密钥管理服务注入，不写入流水线文件
