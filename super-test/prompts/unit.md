# unit — 单元测试规范

## error 级别硬约束

### 1. 每个 public 方法必须覆盖三类场景

每个对外暴露的方法，其单元测试必须覆盖以下三类场景：

**正向场景**：验证方法在正常输入下返回预期结果。至少包含一条最常用的正常调用路径。

**边界场景**：验证方法在输入边界值时的行为。包括：
- 空值（null、空字符串、空集合、0）
- 极值（最大值、最小值、刚好满足条件/刚好不满足条件）
- 特殊值（负数、零长度数组、单元素集合）

**异常场景**：验证方法在异常条件下是否正确抛出或处理异常。包括：
- 外部依赖失败（数据库连接超时、网络调用失败、文件不存在）
- 业务规则不满足（库存不足、余额不够、状态不允许）
- 非法参数（类型不匹配、超出范围、格式错误）

### 2. 单元测试必须 mock 所有外部依赖

单元测试不得依赖真实的外部系统（数据库、网络、文件系统、消息队列）。所有外部依赖必须通过 mock 框架或 stub 对象替代，确保测试：
- 快速执行（毫秒级）
- 结果确定（不受外部环境影响）
- 可并行运行

mock 对象的返回值应模拟真实场景，包括成功返回、异常抛出、超时等。

### 3. 断言必须具体

每个测试用例的断言必须包含对返回值的具体验证，包括：
- 返回值的状态/类型
- 关键字段的值
- 集合的大小和内容
- 异常的异常类型和错误消息

不得仅使用 assertNotNull 或 assertTrue(result) 等笼统断言。断言失败时应提供足够的上下文信息定位问题。

## warn 级别软约束

- 使用参数化测试覆盖多组边界数据
- 测试方法命名采用 should_{预期行为}_when_{条件} 格式
- 覆盖率目标：行覆盖率 ≥ 80%，分支覆盖率 ≥ 70%
