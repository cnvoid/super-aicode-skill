# api — API 测试规范

## error 级别硬约束

### 1. 契约测试：必须验证请求和响应的完整 Schema

每个 API 端点的测试必须覆盖请求体和响应体的完整结构校验：

请求体校验：
- 必填字段缺失 → 400，错误信息指明缺失字段
- 字段类型错误（字符串传数字、数组传对象）→ 400
- 字段格式错误（邮箱格式、日期格式、枚举值）→ 400
- 未声明字段传入 → 400（如开启 whitelist 校验）

响应体校验：
- 成功响应的 `data` 字段包含所有声明的属性且类型正确
- 分页响应的 `data.list` 为数组、`data.total` 为整数、`data.page` 和 `data.pageSize` 为整数
- 可为 null 的字段在无数据时返回 null，不得缺失该字段
- 响应头 `Content-Type` 为 `application/json`

### 2. 状态码覆盖：每个端点的所有可能状态码都要验证

每个 API 端点的一组合格测试必须覆盖该端点文档中所有可能返回的状态码：

| 状态码 | 必须覆盖 |
|--------|---------|
| 200/201 | 正常请求 |
| 400 | 参数校验失败（至少 2 种：必填缺失 + 格式错误） |
| 401 | 未认证（无 Token + 无效 Token + 过期 Token） |
| 403 | 无权限（角色不足 + 跨账号访问他人资源） |
| 404 | 资源不存在（ID 不存在 + 已删除资源） |
| 409 | 数据冲突（重复创建 + 状态不允许操作） |
| 422 | 业务规则不满足（库存不足 + 余额不够） |
| 429 | 超过限流阈值 |
| 500 | 服务端异常（依赖服务不可用、数据库连接失败） |

不得只测试 200 和 400 两个状态码就认为覆盖完整。

### 3. 鉴权全覆盖：每个需认证的端点必须覆盖 5 种鉴权场景

对于需要认证的 API，必须覆盖以下 5 种鉴权失败场景：

- 无 Token（请求头无 Authorization）→ 401
- 无效 Token（随机字符串或已吊销的 Token）→ 401
- 过期 Token（使用过期的 Access Token）→ 401
- 角色不足（普通用户访问管理员接口）→ 403
- 越权访问（用户 A 的 Token 访问用户 B 的资源）→ 403

每个端点至少编写这 5 条鉴权测试，不得合并为 1-2 条笼统的"鉴权测试"。

### 4. 参数边界：每个参数必须覆盖极值和非法值

对每个请求参数的以下取值进行测试：

- 字符串：空字符串、超长字符串（>10000 字符）、含特殊字符（`<script>`、`' OR 1=1`、emoji）
- 数值：0、负数、极大值（Long.MAX 或超出范围）、浮点精度边界（0.1 + 0.2）
- 枚举：合法值、非法值、大小写变体、null
- 数组：空数组 `[]`、单元素、超长数组（1000 个元素）
- 日期：合法日期、无效日期（2024-02-30）、未来日期、1970-01-01

### 5. 幂等验证：写操作重复提交不产生副作用

对 POST 和 PUT 接口进行幂等验证：
- 同一幂等键的 POST 请求发送 2 次 → 第二次返回已有结果，不创建新记录
- 同一数据的 PUT 请求发送 2 次 → 两次结果一致
- DELETE 已删除的资源 → 返回 404 而非 500

## warn 级别软约束

### 6. 限流验证

- 在限流阈值内连续发送请求 → 全部正常返回
- 超过阈值后下一个请求 → 429 + 响应头 `Retry-After` 或 `X-RateLimit-Reset`
- 等待恢复时间后再次请求 → 正常返回

### 7. 版本兼容验证

- 旧版本客户端发送不含新字段的请求 → 服务端以默认值处理，不返回 400
- 新版本响应新增字段 → 旧版本客户端解析不崩溃（新增字段应为可选）
- 废弃接口 → 返回明确的弃用提示（响应头 `Deprecation` 或 `Sunset`）

### 8. 错误体一致性验证

- 所有非 2xx 响应的错误体结构统一为 `{code, message, traceId}`
- `message` 在不同 locale 下返回对应语言描述（如 Accept-Language: zh-CN）
- 5xx 错误的 `message` 不暴露内部实现细节（栈信息、SQL 语句、框架版本）
