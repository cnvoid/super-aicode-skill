# report — 测试报告规范

## error 级别硬约束

### 1. 测试报告必须包含覆盖率数据

每次测试执行后必须输出覆盖率报告，至少包含以下指标：
- 行覆盖率：已执行代码行数占总代码行数的百分比
- 分支覆盖率：已执行条件分支占总分支数的百分比
- 函数覆盖率：已执行的函数占总函数数的百分比

覆盖率报告应标注未覆盖的文件和关键未覆盖分支，帮助定位测试薄弱环节。

### 2. 缺陷必须按严重级别分类

测试报告中发现的每个缺陷必须标注严重级别：

| 级别 | 定义 | 典型场景 |
|------|------|---------|
| P0 | 核心功能不可用 | 支付失败、数据丢失、登录崩溃 |
| P1 | 主要功能异常 | 订单状态流转错误、数据不一致 |
| P2 | 边界场景遗漏 | 超长输入未校验、特殊字符未处理 |
| P3 | 优化建议 | 代码重复、命名不规范、日志缺失 |

### 3. 测试用例必须分类统计

测试报告必须包含测试用例的统计信息：
- 总数、通过数、失败数、跳过数
- 按测试类型分布（单元测试、API 测试、集成测试、E2E 测试）
- 失败的测试用例清单，包含：
  - 用例名称和所在文件
  - 失败原因描述
  - 预期值和实际值的对比
  - 建议修复方向

## warn 级别软约束

- 测试报告包含各阶段执行耗时统计
- 记录历史覆盖率趋势，覆盖率下降触发告警
- 执行时间超过 1 秒的单元测试标记为慢测试，列入优化清单
