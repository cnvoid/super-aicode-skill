# ui — UI 测试规范

## error 级别硬约束

### 1. 组件隔离测试：每个组件独立验证渲染正确性

每个 UI 组件必须有独立的渲染测试，不依赖父组件或全局状态。测试验证：

- 必填 Props 传入 → 组件正常渲染，不抛出渲染异常
- 可选 Props 不传 → 使用默认值渲染，不出现 `undefined` 或空白区域
- Props 极值组合 → 最长文本不溢出、最大数值不截断、0 和负数正确显示
- Slots/children 传入 → 内容在正确位置渲染

```typescript
// 测试结构模式
describe('ComponentName', () => {
  it('renders with required props');
  it('renders with all props');
  it('renders with default values when optional props omitted');
  it('renders slots in correct position');
  it('handles extreme values (long text, zero, negative)');
});
```

### 2. 交互行为测试：所有可交互元素必须验证用户操作

每个可交互的元素（按钮、链接、输入框、下拉框、开关、拖拽区域）必须覆盖对应的用户操作测试：

- 点击：触发预期事件，按钮进入 loading 状态时不可重复点击
- 输入：输入中文/英文/数字/特殊字符，触发校验和受控值更新
- 键盘导航：Tab 聚焦顺序正确、Enter 触发主操作、Escape 关闭弹窗、Arrow 在列表项间移动
- 悬停：tooltip 显示和消失、hover 样式变化
- 拖拽：拖拽起点和终点正确、拖拽过程视觉反馈、释放后数据更新

不得只测试渲染而忽略交互行为。

### 3. 可访问性 a11y：必须通过基础无障碍检查

每个页面和关键组件必须通过以下无障碍验证：

- 所有交互元素使用语义化 HTML 标签（`<button>` 而非 `<div onClick>`）
- 图片有 `alt` 属性，装饰性图片 `alt=""`，信息性图片有描述
- 表单控件有对应的 `<label>` 且通过 `htmlFor` 或嵌套关联
- 颜色对比度满足 WCAG AA 标准（文字 ≥ 4.5:1，大文字 ≥ 3:1）
- 页面有且仅有一个 `<h1>`
- `aria-*` 属性值有效（不引用不存在的 ID）

### 4. 响应式布局：三种断点必须全部验证

组件必须在以下视口宽度下验证渲染正确性：

- 移动端：375px（iPhone SE）和 414px（iPhone 11）
- 平板：768px（iPad mini）和 1024px（iPad）
- 桌面：1280px 和 1920px

验证点：
- 内容不超出视口（无水平滚动条）
- 触摸交互目标最小尺寸 24×24 CSS 像素
- 字体大小在移动端不小于 16px（防止 iOS 自动缩放）
- 弹窗在移动端全屏或宽度自适应，不超出屏幕

## warn 级别软约束

### 5. 状态全覆盖：loading / error / empty / data / 边界

每个数据驱动的组件必须测试以下五种状态：

- loading：骨架屏或 loading 动画正确展示
- error：错误信息和重试按钮可交互
- empty：引导文案和创建入口可见
- data：正常数据渲染正确
- 边界：单条数据、超长文本截断、数值溢出处理、同时满足多个筛选条件的结果为空

### 6. 视觉回归：关键页面的截图比对

对以下页面进行视觉回归测试，与基线截图比对：

- 首页和登录页（首次访问的视觉体验）
- 核心业务页面（订单列表、商品详情）
- 弹窗和通知组件（z-index 遮挡、布局偏移）
- 暗色模式下的关键页面
- 不同字体大小设置下的布局（浏览器默认 / 125% / 150%）

视觉回归工具的像素对比阈值应设置为 1%，允许不同操作系统间的字体渲染微小差异。

### 7. 跨浏览器：Chrome / Firefox / Safari / Edge 一致性

关键用户流程在以下浏览器中验证一致性：

- Chrome（最新版，主流用户）
- Safari（最新版，iOS 用户）
- Firefox（最新版，隐私用户）
- Edge（最新版，企业用户）

验证范围：关键业务路径（登录 → 浏览 → 下单 → 支付），非全量页面。

跨浏览器差异的已知豁免项：滚动条样式、原生表单控件样式、字体渲染差异。
