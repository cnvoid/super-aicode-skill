# integration — 集成测试规范

## error 级别硬约束

### 1. 集成测试使用真实中间件（容器化）

集成测试必须使用真实的中间件实例，不得 mock。中间件通过容器化方式提供：
- 数据库：使用测试专用数据库容器，运行迁移脚本初始化表结构
- 缓存：使用真实的 Redis 容器
- 消息队列：使用真实的消息队列容器

测试容器应在测试套件启动前创建，测试套件结束后销毁。容器的端口应动态分配（映射到随机端口），避免端口冲突。

### 2. 测试数据必须隔离

每个测试用例的测试数据必须独立，不与其他测试用例共享状态。数据隔离策略：
- 每个测试用例使用唯一的前缀或 ID 生成测试数据
- 每个测试用例执行前清空相关表
- 每个测试用例执行后清理自己创建的数据

不得依赖测试用例的执行顺序。

### 3. 关键业务流程必须端到端验证

核心业务路径必须通过集成测试端到端验证完整的业务流程。验证应覆盖业务状态机的每个转换步骤，确保各环节正确衔接。

示例流程（订单）：创建 → 支付 → 发货 → 签收 → 完成
示例流程（退款）：申请 → 审核 → 退款执行 → 到账确认

## warn 级别软约束

- 集成测试不 mock 数据库和缓存，使用真实容器
- 消息队列测试需验证消息的发送和消费的正确性
- 单次集成测试的数据量控制在 100 条以内
- 集成测试独立于单元测试运行，不在开发阶段频繁执行
