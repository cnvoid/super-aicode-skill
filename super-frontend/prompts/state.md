# state — 状态管理规范

## error 级别硬约束

### 1. Store 必须按业务模块拆分

全局状态管理必须按业务领域拆分为独立的 Store 模块，每个模块管理单一领域的状态。禁止将所有状态放入单一巨型 Store 中。

拆分粒度：一个业务实体（如用户、订单、商品）对应一个 Store 模块。跨模块的数据交互通过 Action 调用其他 Store 的方法实现，不得直接修改其他 Store 的 State。

### 2. 异步操作必须覆盖三态

所有异步数据获取操作（API 调用）必须管理以下三种状态：

- loading：请求进行中，UI 展示加载态
- error：请求失败，UI 展示错误信息及重试入口
- data：请求成功，UI 展示业务数据

Store 中对应每个异步操作维护这三个状态字段，不得只有 data 字段而忽略 loading 和 error。

## warn 级别软约束

- 避免将服务端返回的原始数据结构直接存入 Store，需经过一层数据转换（日期格式化、枚举映射、字段重命名）
- 对于不需要全局共享的状态（仅单页面使用），使用组件内部 State 或页面级 Store，不放入全局 Store
- Store 中的计算派生数据使用 Getter/computed 实现，不冗余存储
- 持久化到 localStorage 的 Store 数据必须通过白名单控制，敏感信息（Token、密码）不得持久化
