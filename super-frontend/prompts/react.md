# react — React 组件规范

## error 级别硬约束

### 1. 组件必须职责单一

每个组件只承担一个职责——要么负责展示，要么负责数据获取，要么负责状态管理，不得将一个组件的职责混合。

判断标准：能用一句话描述组件的职责且不包含"和"字。如果描述中出现"和"（如"展示订单列表和处理删除操作"），则组件职责过多，需要拆分。

违反单一职责的信号：
- 组件内部有多个互不相关的 state
- 组件 Props 数量超过 8 个
- 组件的 useEffect 超过 3 个且互不相关
- 组件代码超过 200 行

### 2. Props 必须设计为最小接口

组件 Props 只暴露使用者真正需要控制的属性。内部状态、内部逻辑的实现细节不得作为 Props 暴露。

Props 的设计原则：
- 必填 Props 仅设置核心数据（如 id、data）
- 可选 Props 提供合理的默认值，确保不传 Props 时组件能正常渲染
- 不得将整个 API 响应对象作为 Props 传递——组件只接收它实际使用的字段
- 回调函数 Props 使用 on{Event} 命名（如 onSubmit、onDelete、onClose）

### 3. 优先使用组合而非继承或高阶组件

组件复用必须优先使用组合模式（children prop / render props / slots），而非高阶组件（HOC）或组件继承。

组合的优势：
- 组件树结构显式可见，不被 HOC 包裹隐藏
- Props 流向清晰，不产生"Props 来自哪个 HOC"的困惑
- 更易于 TypeScript 类型推导

### 4. 可复用逻辑必须抽离为自定义 Hook

跨组件复用的状态逻辑必须封装为自定义 Hook，不得在多个组件中复制粘贴相同的 useState + useEffect 组合。

自定义 Hook 以 use 前缀命名，返回清晰的数据结构。Hook 内部必须处理加载、错误、数据三种状态，不得将错误直接抛给调用组件。

### 5. 每个组件树必须有错误边界

每个独立的页面或功能模块的组件树根部必须包裹错误边界组件。错误边界捕获渲染期间的异常，防止单个组件崩溃导致整个页面白屏。

错误边界必须是 class 组件，实现 componentDidCatch 或 static getDerivedStateFromError。错误边界捕获异常后应记录错误日志并展示降级 UI。

### 6. 列表渲染必须使用稳定的唯一 key

使用数组渲染列表时，每个子项必须分配一个在列表范围内唯一且稳定的 key 属性。key 使用业务数据唯一标识，不得使用数组索引。

### 7. 副作用必须清理

useEffect 中创建的定时器、订阅、事件监听、网络请求，必须在返回的清理函数中销毁或取消。组件卸载时未清理的副作用导致内存泄漏。

## warn 级别软约束

- 容器组件与展示组件分离：容器负责数据获取和状态管理，展示组件只通过 Props 接收数据并渲染
- 异步操作使用统一的 loading/error/data 三态管理
- props 跨层级超过 3 层使用 Context 或状态管理库
- 列表图片使用懒加载
- 表单使用受控组件模式
- 组件文件与组件同名，一个文件只导出一个主组件
