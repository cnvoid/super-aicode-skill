# component — 通用业务组件封装规范

## error 级别硬约束

### 1. 弹窗必须有统一的层级管理

项目中所有弹窗组件（Modal、Dialog、Drawer、Popover、Toast、Dropdown）的 z-index 必须通过集中常量统一管理，不得在各个组件内硬编码 z-index 数值。

层级常量按功能分层定义（由低到高）：
- 基础层（100-199）：Dropdown、Popover、Tooltip 等悬浮组件
- 弹窗层（200-299）：Modal、Dialog
- 抽屉层（300-399）：Drawer
- 通知层（400-499）：Toast、Notification、Message
- 遮罩层（500-599）：Loading、全屏遮罩
- 顶层（600-699）：全局水印、引导蒙层

弹窗嵌套场景（Modal 中再弹出 Modal）时，内层弹窗的 z-index 必须在当前弹窗的基础上递增。不得出现"内层弹窗被外层遮挡"的问题。

### 2. 弹窗关闭时必须清理副作用

弹窗组件关闭时必须执行以下清理：
- 重置弹窗内的表单数据和校验状态
- 取消弹窗内发起的未完成请求
- 移除弹窗内注册的事件监听
- 清除弹窗内创建的定时器

不得在关闭弹窗后，其内部副作用仍然存在并影响页面。

### 3. 通用业务组件必须跨页面复用

以下高频业务组件不得在每个页面重复实现，必须抽取为通用组件：

- 列表搜索区（SearchBar/FilterBar）：搜索框 + 筛选条件 + 搜索/重置按钮
- 列表表格区（DataTable）：分页表格 + 多选 + 排序 + 列配置
- 表单编辑区（EditForm）：新增/编辑表单 + 校验 + 提交
- 详情展示区（DetailPanel）：字段-值对照展示
- 确认弹窗（ConfirmDialog）：二次确认操作

通用组件通过 Props 接收差异化配置（列定义、表单字段、API 调用函数），不得将业务逻辑写死在组件内部。

### 4. 弹窗内容独立为一个组件

弹窗内的业务内容必须封装为独立组件，弹窗容器只负责显隐控制和层级管理。禁止在页面文件中以内联方式直接写大段弹窗内容 JSX。

## warn 级别软约束

- 弹窗打开时阻止背景页面滚动，弹窗关闭时恢复
- 确认弹窗的取消按钮始终在左，确认按钮在右；危险操作确认按钮使用警告色
- 删除/禁用等不可逆操作必须使用二次确认弹窗，确认按钮文案明确操作后果（如"确认删除"而非"确认"）
- 图片/文件预览弹窗支持键盘左右切换和 ESC 关闭
- 列表页面提供空状态（数据为空）、加载态、错误态三种展示
- 时间段选择组件对开始时间 > 结束时间自动交换
